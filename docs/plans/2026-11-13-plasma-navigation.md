# Plasma navigation landing

The homepage combines a compact navigation input, a swipeable suggestion rail, and original 3D sculptures rendered through the existing playground luminance pipeline. It retains the monochrome plasma, typography, and legal navigation. This version handles navigation and animation commands locally; it does not send messages to an AI service.

On desktop (768px and up), the icon is the hero: its stage is centered one third down the viewport, the center of the upper two thirds. Its stage grows to 56% of the viewport height, with the input beginning at 72%. Those anchors remain stable when search results appear; results and the expanded introduction flow below. Short desktop windows use a 600px minimum composition so controls remain accessible by scrolling. The icon stage blends with the plasma backdrop rather than exposing its black canvas background. Mobile retains the compact, flowing hero and stacks the introduction in a single column.

The introduction below the fold expands the existing public profile into a short first-person description of Alex's approach, UX/frontend/AI work, and interest in untangling interfaces and workflows. The name, location, project exploration, contact, and external profile links remain server-rendered, with existing Button components reused for the calls to action.

Suggestions open experience (labelled “Explore projects”), contact, the CV PDF, the plasma playground, and the new `/hire` directory. Project-related navigation resolves to `/cv`. Complete navigation and playback commands take priority over search, while descriptive queries such as “React projects” or “PDF generation” remain searches. Links remain real anchors for keyboard access and navigation without JavaScript.

Focusing the input loads the existing public `/api/projects` index once. All matching then happens locally with no LLM backend and no request per keystroke. Typing replaces the default rail with matching project names and keywords from tools, expertise, industries, languages, project types, workplaces, client names, and featured status. Chips show their category and project count; selecting a keyword applies its exact field. Multiple terms can match across fields, with project-name matches ranked before incidental summary mentions. Short queries such as “AI” support acronyms without matching unrelated substrings such as “Tailwind”.

Matching projects appear in a compact scrollable panel and link directly to their detail pages. Arrow keys change the active suggestion and its icon/caption; Enter selects it, and Escape clears the query and restores the default rail. Loading, retry, and empty states stay within the same console. Search consumes only public project metadata and retains only the fields needed for matching and local links.

A shared active suggestion drives the caption and 3D icon. Idle cycling pauses while the user interacts or types. Hover previews do not move their click targets; keyboard focus and idle cycling center the rail, while arrows scroll it in their indicated direction. Each arrow and edge fade is visible only when content remains in that direction; measurements update on scrolling and resizing. The icon fades, moves, and scales between shapes. Dragging uses the playground's OrbitControls with zoom and pan disabled. Automatic rotation pauses during interaction. Explicit pause and reduced motion disable camera damping. Hidden/offscreen scenes release their rendering resources.

The original models use rounded, layered geometries and per-part monochrome tones: folder and papers, envelope and letter, briefcase, folded CV sheet, gear, and torus knot. A directional key and fill light retain their volume through the character texture. Source geometries are generated locally without external model downloads.

Project-specific models use filled Font Awesome silhouettes exported from the existing React Icons package, converted into centered, beveled solids with preserved holes and darker side walls. React and React Native tool chips use a procedural atom with three tubular elliptical rings and a spherical nucleus. The scene builds additional icons only when selected, reuses them within that scene, and releases them with its existing resources. Highlighting project chips or hovering/focusing a result drives the matching model and caption through the existing transition and drag-rotation controls.

Project icon choices live in the Projects database's **3D Icon** select in Notion. All 38 published projects were populated; existing logos, page icons, and other properties were preserved. The runtime has no project-to-icon map. It accepts only supported icon names and uses a folder for blank or unknown values. The historical seed map in `ops/notion/project-icons-seed.json` is used only by the repeatable migration script, which preserves existing selections. `getCachedProjectIcons` refreshes icon metadata independently of static CV content with a 300-second server cache; the public list API uses a 60-second shared cache with 30-second stale-while-revalidate. A newly focused search loads the latest available index; an already-open search keeps its snapshot until reload.

Run `node scripts/generate-landing-icons.mjs` after changing the bundled symbol catalog. The generated SVGs are trusted local assets and never come from user input or remote raster tracing. Icon attribution is retained beside the assets.

The 3D shader uses a 128-step mirrored brightness wave. Both the reversal and the cyclic join have matching samples, avoiding the former bright-to-dark discontinuity. The existing background already has a mirrored character palette. The shared shader change also applies to playground shapes.

The hiring directory reuses Layout, IconLink, and Button. Profile URLs for Malt and freelancermap were supplied by the owner; LinkedIn and direct email reuse existing site links. The page is discoverable from the rail, site navigation, contact page, and sitemap.

Validation covers command resolution, unknown input, rail boundary availability, crawlable hiring links and canonical metadata, mirrored-wave boundary continuity, existing SEO/API tests, TypeScript, ESLint, formatting, production build, and browser checks at phone and desktop sizes. Browser checks include typed hiring navigation, chip/icon synchronization, drag rotation while paused, and the email icon/text alignment fix in the shared IconLink component.

Search validation adds behavioral coverage for every keyword group, partial and combined queries, project-name ranking, exact filters, local result URLs, and command/search ambiguity. Browser checks cover the live 38-project index, keyboard and mouse keyword selection, project-detail navigation, restoring the default rail, empty results, and 320px/390px layouts without horizontal overflow.

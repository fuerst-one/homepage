# English and German website

The canonical page URLs use `/en` and `/de`. Both languages share the same route components under `src/app/[locale]`. The locale root layout validates the language and renders the HTML `lang` on the server. Existing English URLs permanently redirect to their `/en` equivalents. German legal pages use `/de/impressum` and `/de/datenschutz`; English uses `/en/legal-notice` and `/en/privacy`.

APIs, image routes, static assets, `robots.txt`, `sitemap.xml`, and `llms.txt` stay unprefixed. There is no automatic browser-language redirect. Language links preserve the current page and query filters. The homepage links expose both languages without JavaScript.

## Editing in Notion

Projects retain one record per project, shared names/IDs, tags, multiselects, dates, clients, logos and screenshots. Translated rich-text properties are **Project Description DE** and **KPIs DE**. **German ready** publishes a translation only when its description and all nonempty source KPI prose are translated. Clear the checkbox while revising a translation or changing the English source. Unpublished projects fall back to English links in German lists; their German detail pages and sitemap alternates are not published. Raw translation source fields do not cross public API or client-component boundaries.

The owner contact record has **Position DE**, **Status DE**, **Languages DE**, and **Education DE**. English properties remain intact.

Main homepage, CV, contact, hiring and PDF prose is in [Fuerst.one · Site Copy](https://www.notion.so/41786514f7368196bcaac768bbbd738d). Each row has a stable **Key**, **English**, and **German** value. The database lives under the owner contact page because the project database is at workspace root. Its ID is in `src/data/notion-site-copy.json`; an optional `NEXT_NOTION_SITE_COPY_DB_ID` overrides it. These are source IDs, not credentials. All Notion access remains server-side using the existing token.

UI labels and CV preset explanations are translated in code. Technology names, database option values, project names and technical experiment labels can remain shared. The service-page session owns curated bilingual service copy in `src/data/services.ts` and reuses published Notion project evidence.

## Backfill and refresh

`node --env-file=.env.local scripts/seed-notion-translations.mjs` previews changes. Add `--apply` to seed missing fields and copy rows. The script preserves existing German text, source rich-text links/annotations, and English content. It checks source hashes before applying the curated project seed. Re-running after this migration proposes zero changes. The seed files are historical migrations; the website reads Notion directly, not those seed files.

Public source data and prerendered pages use 3600-second revalidation. New translations and edits become available through cache revalidation; an already-open browser retains its loaded snapshot until navigation/reload. Published locale pages, reciprocal language alternates and the sitemap use shared path/publication helpers. The build prerenders both languages. PDFs render on demand at `/en/cv.pdf` and `/de/cv.pdf` using the same locale-selected data.

Public profile/project APIs accept `?locale=en|de`, defaulting to English. German list API detail URLs retain `locale=de`. `webUrl` points to the actual published page language. Invalid locale parameters return 400; unsupported page/PDF locale paths return 404.

## Release and verification

This implementation changes the sitemap generator, not its public URL. Deploy the matching routes, permanent redirects, internal links, metadata and sitemap together. Then verify the live sitemap and representative English/German pages before updating Search Console or changing the indexing monitor's canonical targets. No DNS or legacy-host configuration changes are part of this implementation.

Initial acceptance: 41 public project translations, owner fields and 21 Site Copy rows backfilled. Production build generated 82 project pages plus the shared locale pages and four service pages. All 102 sitemap URLs returned 200 with self canonicals and matching HTML languages on the isolated production server. The final 88-test suite passed. Browser and PDF acceptance evidence is recorded in the [completion receipt](i18n-acceptance-2026-11-13.md).
